# 조직 대시보드 연결

2026-10-06: 운영 관리 이동은 공통 GNB 대신 활용 페이지의 `조직 대시보드` 영역에서 안내합니다. 홈의 활용 영역도 이 소개로 연결합니다. 시스템 구현 자료의 기존 링크는 같은 목적지를 재사용합니다.

## 주소와 데이터 범위

- 공개 목적지: https://sdg331.github.io/CarpeDM_EXPO_Microsite/dashboard/#/overview
- 대시보드 소스: 별도 `CarpeDM_EXPO_dashboard` 저장소의 `46403fa`. 회사 운영 개요, 팀·사원 관리, 체험과 리포트를 보여주는 샘플 워크스페이스입니다.
- 예시 데이터이며 실제 직원 정보·AI 분석·현장 장치와 연결되지 않습니다. 사용자가 변경한 예시 정보는 해당 브라우저에 저장됩니다.
- `src/data/paths.ts`는 개발에서 로컬 4174를, 프로덕션에서 HTML의 `data-site-root`를 사용한 같은 사이트 `dashboard/#/overview`를 기본값으로 사용합니다. 홈·상세·저장소 하위 경로에서 같은 목적지가 됩니다.
- `VITE_DASHBOARD_URL`로 절대 HTTP(S) 목적지를 재정의할 수 있습니다. 명시적 빈 값은 직접 링크를 숨기고, 잘못된 프로토콜·상대 주소는 거부합니다. 값은 공개 번들에 포함되므로 비밀을 넣지 않습니다.
- 대시보드 새 탭 링크에 `noopener noreferrer`와 샘플 워크스페이스·새 탭 접근성 설명을 제공합니다.

## 배포 순서

1. 마이크로사이트에서 `npm run lint`, `npm run typecheck`, `npm run build`, `node --test tests/*.mjs`를 실행합니다. 기본 목적지를 쓸 때는 `VITE_DASHBOARD_URL`을 설정하지 않습니다.
2. 별도 대시보드 최신 소스에서 lint/typecheck/test/build를 수행합니다. `base: './'`과 해시 경로를 유지합니다.
3. 마이크로사이트 빌드 이후 대시보드 `dist/` 내용물을 마이크로사이트의 `dist/dashboard/`에 복사합니다. 마이크로사이트를 다시 빌드하면 이 폴더도 재복사해야 합니다.
4. 완성된 `dist/`와 `.nojekyll`을 기존 `gh-pages` 루트에 정상 커밋·push합니다. 빌드 산출물은 소스 `main`에 커밋하지 않습니다.
5. Pages 빌드 커밋과 공개 페이지의 새 JS 파일을 확인하고 활용 → 대시보드 → 서비스 소개 이동을 검수합니다.

실제 검증 결과와 미검증 범위는 `qa.md`에 기록합니다. 자동 배포 워크플로·백엔드·관리자 인증은 추가하지 않습니다.
