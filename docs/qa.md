# 검증 체크리스트

이 문서는 최초 구현과 이후 변경에 공통으로 사용하는 검증 기준이다. 체크 표시는 실제 실행·관찰한 항목에만 적용한다. 코드 검토, 브라우저 확인, 빌드 성공은 서로 다른 증거이며 한 가지로 다른 검증을 대체하지 않는다.

## 현재 검증 상태

최근 UI 검증일: **2026-09-22**. 최신 기록은 하단의 “제품 중심 재구성 및 글래스 아이콘”이다. 아래 상태는 실제 명령 실행, 브라우저 관찰 또는 코드 검토 결과를 구분해 기록한다. 하단 체크리스트는 이후 변경에도 재사용하는 절차이며, 완료 기록을 대신하지 않는다.

## 검증 준비

1. `docs/product.md`, `docs/design.md`, `docs/content.md`, `docs/architecture.md`를 읽고 이번 변경 범위를 확인한다.
2. README의 Node.js 요구 사항과 `package.json`의 실제 스크립트를 확인한다.
3. 최초 설치는 `npm install`을 사용한다. 유효한 잠금 파일이 있는 재현 환경에서는 `npm ci`를 사용한다.
4. 개발 화면은 `npm run dev`로 `http://localhost:5174`에서, 프로덕션 결과는 빌드 후 `npm run preview`로 `http://localhost:4175`에서 실행한다.
5. 이번 변경에 관련된 항목을 검증한다. 최초 구현과 배포 전에는 전체 체크리스트를 확인한다.

검증만을 위해 자동화 패키지나 프로덕션 의존성을 추가하지 않는다. 사용 가능한 브라우저 도구와 기존 npm 스크립트를 우선 사용한다. 사용할 수 없는 도구로 인한 미검증 항목은 그대로 남긴다.

- [ ] 프로젝트 명칭, 목적, 두 디바이스의 역할이 `docs/product.md`의 확인된 사실과 일치한다.
- [ ] 구현 예정인 체험 흐름과 이미 구현된 기능을 구별한다. 초기 소개 문구가 구현 완료의 근거로 사용되지 않는다.
- [ ] 사용자 수, 인식률, 지연 시간, 수상 실적, 제휴, 사용성 실험 결과 등을 근거 없이 주장하지 않는다.
- [ ] 등록 → ID/NFC 연결 → Smart Mirror → 인식 → 음성·화면 상호작용 → 개인화의 의도된 순서가 명확하다.
- [ ] 확인되지 않은 기능은 목표·설계 방향으로 설명하고 내부 TODO를 확인된 사실로 바꾸지 않는다.
- [ ] 대외 문구가 `docs/content.md`와 일치하며 한국어가 주 언어로 유지된다.
- [ ] 정확한 하드웨어 모델은 기술 상세에서 확인할 수 있고 방문자 소개를 압도하지 않는다.
- [ ] 도식·실루엣·미디어 대체 화면이 실제 제품 사진이나 완료된 제품의 증거로 오인되지 않는다.
- [ ] 실제로 제공하지 않는 로그인, 구매, 가격, 체험 예약, 가짜 추천사 또는 고객 로고가 없다.

## 화면 크기별 확인

각 폭에서 페이지 전체를 스크롤한다. 뷰포트 높이와 브라우저를 증거에 함께 기록한다. 개발자 도구의 화면 폭 변경은 실제 모바일 기기의 터치·브라우저 동작 검증을 대체하지 않으므로 구분해서 기록한다.

| 뷰포트 폭 | 대상 | 중점 확인 | 상태·증거 |
| --- | --- | --- | --- |
| 360 px | 좁은 모바일 | 제목 줄바꿈, 메뉴, 세로 체험 흐름, 아키텍처, 터치 영역 | 360×900 DOM 확인, 360×800 열린 하드웨어 상세 가로 넘침 없음 |
| 390 px | 모바일 | 본문 읽기 폭, 제품 프레임, 헤더, 섹션 여백 | 390×900 DOM 확인, 390×844 Hero·세로 timeline·메뉴·상세 화면 확인 |
| 768 px | 태블릿 | 메뉴 전환, 그리드 전환, 가로·세로 구성의 연결 | 768×900 DOM 3열 흐름, 768×1024 Hero 화면 확인 |

| 1280 px | 데스크톱 | 편집형 그리드, 콘텐츠 최대 폭, 제품 비중 | 1280×900 DOM 및 Smart Mirror/Kiosk 화면 확인 |

- [ ] 헤더부터 푸터까지 필수 섹션이 순서대로 표시된다.
- [ ] 모바일은 체험 흐름을 세로로 읽을 수 있으며 제품과 기술 도식이 화면 폭에 맞는다.
- [ ] 모든 폭에서 가로 스크롤, 잘린 제목, 겹친 본문, 잘린 포커스 표시가 없다.
- [ ] 화면 폭뿐 아니라 브라우저 200% 확대에서도 주요 콘텐츠와 조작이 가능하다.
- [ ] 영문 제목과 한글 본문은 실제 시스템 폰트에서도 깨지지 않는다. 외부 폰트 설치를 전제로 검사하지 않는다.
- [ ] 긴 기술명과 예상보다 긴 문구가 줄바꿈되어 인접 요소를 밀어내지 않는다.
- [ ] 모바일 조작 영역은 최소 44 × 44 CSS px를 목표로 충분히 확보한다.
- [ ] 고정 헤더가 앵커 이동한 섹션 제목이나 현재 포커스를 가리지 않는다.
- [ ] 본문, 제품 프레임, 도식, 섹션 간 여백이 `docs/design.md`의 의도와 일치한다.

## 키보드·의미 구조·접근성

- [ ] 건너뛰기 링크가 키보드로 드러나고 본문으로 이동한다.
- [ ] Tab과 Shift+Tab 순서가 시각적 읽기 순서와 일치하며 포커스가 항상 보인다.
- [ ] 모든 내비게이션 링크와 CTA를 키보드로 사용할 수 있다.
- [ ] 모바일 메뉴 버튼에 이해할 수 있는 접근 가능한 이름과 올바른 펼침 상태가 있다.
- [ ] 메뉴는 키보드로 열리고 Escape로 닫히며 닫힌 뒤 메뉴 버튼으로 포커스가 돌아간다.
- [ ] 메뉴 링크를 선택하면 목적지로 이동하고 메뉴가 닫힌다. 숨긴 메뉴 링크에 포커스가 남지 않는다.
- [ ] 메뉴를 연 상태로 데스크톱 폭으로 바꾸어도 불필요한 스크롤 잠금이나 숨김 상태가 남지 않는다.
- [ ] 메뉴 구현 방식에 적합한 포커스 동작을 사용한다. 모달인 경우에만 배경 접근 제한과 포커스 가두기를 검증한다.
- [ ] `header`, `nav`, `main`, `footer`와 섹션 제목의 관계가 명확하다.
- [ ] 페이지의 핵심 제목은 하나의 `h1`이고 이후 제목 단계가 논리적이다.
- [ ] 링크·버튼·이미지에 의미 있는 이름이 있다. 의미 없는 장식은 빈 alt 또는 적절한 숨김 처리를 한다.
- [ ] 이미지에만 중요한 문구나 체험 단계가 담겨 있지 않다.
- [ ] 네이티브 HTML 의미에 불필요한 ARIA를 중복하지 않는다.
- [ ] 어두운 배경에서 일반 텍스트 대비는 4.5:1 이상, 큰 텍스트와 필요한 UI 경계·포커스는 3:1 이상인지 확인한다.
- [ ] 보조 문구도 읽을 수 있다. 색상만으로 링크·선택 상태·정보 차이를 전달하지 않는다.

## 모션과 점진적 표시

- [ ] 운영체제 또는 브라우저 도구에서 `prefers-reduced-motion: reduce`를 켜면 이동·스크롤·등장 모션이 제거 또는 최소화된다.
- [ ] 모션 감소 상태에서도 모든 콘텐츠가 즉시 읽히며 레이아웃이나 메뉴 기능이 유지된다.
- [ ] 일반 모션 상태에서 빠르게 스크롤하거나 중간 앵커로 진입해도 섹션이 영구적으로 숨겨지지 않는다.
- [ ] IntersectionObserver 미지원 또는 등장 효과 초기화 실패 시 이미 렌더링된 본문을 읽을 수 있다.
- [ ] 등장 효과 이전에도 포커스 가능한 요소가 보이지 않는 조작 대상으로 남지 않는다.
- [ ] 지속적인 반복 효과, 스크롤 가로채기, 읽기를 지연시키는 전환이 없다.

이 항목은 등장 효과의 점진적 향상을 검증한다. React 클라이언트 렌더링 페이지의 JavaScript 비활성화 지원을 확인했다고 오해하지 않도록 검증 범위를 기록한다.

## 이미지·미디어 대체 화면

- [ ] 실제 사진을 제공하지 않은 기본 상태에서 깨진 이미지 아이콘이나 빈 영역 대신 의도된 제품 표현이 보인다.
- [ ] 정상 로드되는 로컬 이미지를 넣었을 때 지정한 비율·잘림·대체 텍스트가 유지된다.
- [ ] 잘못된 이미지 경로나 네트워크 로드 실패를 일시적으로 재현하면 기본 대체 화면으로 복구된다.
- [ ] 실패한 이미지가 무한 재시도하거나 반복 오류를 만들지 않는다.
- [ ] 제품 미디어 영역의 공간이 미리 확보되어 로드 전후 큰 레이아웃 이동이 없다.
- [ ] 첫 화면의 중요 이미지는 불필요하게 지연 로드하지 않고 하단 이미지는 적절하게 지연 로드한다.
- [ ] 실제 사진을 추가할 때 파일 형식, 크기, 반응형 소스와 의미 있는 alt를 확인한다.
- [ ] 이미지 교체 절차와 권장 파일명이 README 및 아키텍처 문서와 일치한다.

이미지 실패 재현을 위해 바꾼 임시 경로나 테스트 파일은 검증 후 원복한다. 기본 사진이 없는 상태를 확인한 것과 실제 이미지의 성공·실패를 확인한 것은 별도로 기록한다.

## 링크·배포·로딩

- [ ] 모든 내비게이션과 CTA의 해시 대상이 존재하고 ID가 중복되지 않는다.
- [ ] 해시 URL로 직접 진입하거나 새로고침해도 해당 섹션을 사용할 수 있다.
- [ ] 외부 링크는 실제 목적지를 사용하고 가짜 URL·SNS 계정이 없다.
- [ ] 루트 경로와 저장소 하위 경로 배포를 각각 확인한다. 하위 경로 예: `/CarpeDM_EXPO_Microsite/`.
- [ ] 상대 base 설정에서 JS·CSS·favicon·제품 이미지가 올바르게 로드되고 자산 404가 없다.
- [ ] 하위 경로에서 페이지 내 앵커 클릭 후에도 현재 배포 경로가 유지된다.
- [ ] 문서의 `lang="ko"`, 제목, 설명, viewport, theme-color와 Open Graph 구조가 맞다.
- [ ] 미확정 공개 URL이나 실제로 없는 공유 이미지를 metadata에 넣지 않는다.
- [ ] 외부 웹 폰트·CDN·분석 도구·원격 API에 의존하는 런타임 요청이 없다.
- [ ] 프로덕션 네트워크 패널에서 불필요한 요청, 자산 오류, 대용량 원격 미디어가 없는지 확인한다.
- [ ] 느린 네트워크에서 핵심 문구와 CTA가 늦게 가려지거나 이미지 때문에 크게 이동하지 않는다.
- [ ] 브라우저 콘솔에 처리되지 않은 예외, React 경고, 자산 로드 오류가 없다.
- [ ] 프로덕션 번들에 비밀 키·개인정보·개발 전용 데이터가 없다.

로컬 미리보기 성공은 실제 호스팅 완료를 의미하지 않는다. 하위 경로 검증도 실행하지 않았다면 설정 검토 결과만 기록한다. 네트워크 요청 없음은 초기 HTML·JS·CSS 등 정적 자산 로드를 제외한 외부 런타임 의존성이 없음을 뜻한다.

## 명령 검증

아래 명령을 각각 실행하고 실제 결과를 기록한다. 실패하면 원인을 해결한 뒤 관련 명령을 다시 실행한다.

```sh
npm run lint
npm run typecheck
npm run build
```

- [ ] ESLint가 종료 코드 0으로 완료된다.
- [ ] TypeScript 검사가 종료 코드 0으로 완료된다.
- [ ] Vite 프로덕션 빌드가 종료 코드 0으로 완료된다.
